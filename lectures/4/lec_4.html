Лекция 4#

  1. Любая последовательность — это контейнер, потому что в ней можно проверить наличие элемента (x in seq).

  2. Но не любой контейнер — это последовательность. Например:

  • set и frozenset — контейнеры, но не последовательности: в них нет индексов и порядка (в современных версиях Python порядок сохраняется при вставке, но это не делает их последовательностями по протоколу).

  • dict — контейнер, и в нём есть порядок вставки, но он не является последовательностью: нельзя взять элемент по произвольному индексу как в списке, а протокол последовательности не реализован.

class Point:
    "Класс для представления координат точек на плоскости"
    color = 'red'
    circle = 2

    def __init__(self, x, y):
        self._x = x
        self._y = y

    def change_x(self, x):
        self._x = x

    def change_y(self, y):
        self._y = y

    def set_coords(self, x, y):
        self.change_x(x)
        self.change_y(y)

    def drow_point(self):
        print(f'im drowing the point at x = {self.x}, y = {self.y}')

a = Point(5, 2)

Git#

База#

Каждый студент и научный сотрудник рано или поздно сталкивается с ситуацией, когда в папке с лабораторной или расчетной программой появляются файлы со следующими именами:

program.py, program_v2.py, program_final_1_fixed.py, program_точно_последняя_версия_правка.py.

При попытке объединить код, написанный вдвоем с напарником по лабе, выясняется, что кто-то затер чужие изменения, а воспроизвести результаты трехдневной давности уже невозможно. Для решения этой фундаментальной проблемы хаоса в коде и документации существуют системы контроля версий (Version Control Systems, VCS), среди которых промышленным и академическим стандартом де-факто является Git.

1. Важность использования Git в учебе и науке#

  1. История и воспроизводимость экспериментов. Git хранит пошаговую историю каждого изменения: кто, когда и что именно изменил.

  2. Безопасность экспериментов («Машина времени»): Можно смело переписывать алгоритм, оптимизировать вычисления или добавлять новые физические модели. Если эксперимент провалился, вы в одну команду можете вернуться к стабильно работающей версии.

  3. Командная работа без боли: Никаких пересылок архивов по почте или через мессенджеры. Git позволяет нескольким людям работать над одним проектом параллельно, автоматически объединяя их изменения и разрешая конфликты.

  4. Интеграция с современными средами: Git «из коробки» поддерживается в VS Code, интегрируется с платформами для хранения кода (GitHub, GitLab) и используется во всех IT-компаниях и научных лабораториях мира.

2. Архитектура и основные концепции Git#

В отличие от старых систем (например, SVN), которые хранят «разницы» (diffs) между файлами, Git работает иначе:

  • Снимки (Snapshots): При каждом сохранении (коммите) Git делает полный «снимок» состояния всех файлов проекта в этот момент времени. Если файл не изменился, Git просто сохраняет ссылку на его предыдущую версию.

Три основных состояния файлов в Git:#

  1. Working Directory (Рабочая директория): Папка на вашем диске, где вы редактируете код (например, файлы main.cpp, settings.json).

  2. Staging Area / Index (Индекс / Область подготовки): Промежуточная зона, куда вы отбираете файлы, которые войдут в следующую версию.

  3. Repository / .git (Репозиторий): Локальная база данных, где надежно хранятся все снимки и история проекта.

4. Основные функции и базовые команды#

Для повседневной работы над учебными проектами и лабораторными работами достаточно знать базовый набор команд Git:

  • Инициализация или клонирование:

  • git init — создать пустой локальный репозиторий в текущей папке.

  • git clone <url> — скопировать существующий удаленный репозиторий (например, с GitHub).

  • Фиксация изменений (Workflow):

  • git status — проверить текущее состояние репозитория (какие файлы изменены, какие добавлены в индекс).

  • git add <файл> — добавить файл из рабочей директории в индекс (подготовить к коммиту).

  • git commit -m "описание изменений" — создать «снимок» (коммит) с пояснением того, что было сделано.

  • Анализ истории:

  • git log — посмотреть хронологический список всех коммитов, их авторов и хеш-сумм.

  • Ветвление (Branching) — ключевая функция для экспериментов:

  • git branch <имя> — создать новую ветку (например, для тестирования нового численного метода).

  • git switch <имя> (или git checkout) — переключиться на нужную ветку.

  • git merge <имя> — слить изменения из другой ветки в текущую.

  • Взаимодействие с удаленными серверами:

  • git push — отправить локальные коммиты на удаленный сервер (GitHub/GitLab).

  • git pull — скачать свежие изменения с удаленного сервера и объединить их с вашим кодом.
